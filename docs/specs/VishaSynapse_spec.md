# VishaSynapse 기획서 (초안)

## 1. 목적

VishaSynapse는 방송·버추얼 활동에 쓰는 여러 프로그램과 서비스를 **한 곳에서 연결하는 중계 허브 서버**다.
각 프로그램은 VishaSynapse에 WebSocket으로 접속하고, VishaSynapse는 목적지에 따라 메시지를 전달한다.
치지직 채팅처럼 외부 서비스의 이벤트도 받아서 연결된 프로그램들에 전달한다.

`[확인 필요]` README에는 "REST API"라고 되어 있지만, 현재 코드에는 REST(HTTP) 엔드포인트가 없고 WebSocket만 있다. REST API가 필요한지, README 표현만 고치면 되는지 정해야 한다.

## 3. 기능 요구사항

### F-1. 중계 서버 (허브)
- F-1-1. 클라이언트가 접속하면 서버가 `[0, 0]`을 보낸다.
- F-1-2. 클라이언트는 30초 안에 `[0, 1, deviceType]`으로 자신을 등록한다. 서버는 `[0, 1]`로 응답한다.
- F-1-3. 30초 안에 등록하지 않은 클라이언트는 연결을 끊는다.
- F-1-4. **등록된 클라이언트만** 메시지를 보낼 수 있다.
- F-1-5. 메시지의 첫 바이트(목적지)와 같은 `deviceType`을 가진 모든 클라이언트에게 메시지를 그대로 전달한다.
- F-1-6. 서버 포트는 설정 파일(`config.json`의 `SocketPort`)에서 정한다.
- `[확인 필요]` 같은 `deviceType`의 클라이언트가 여러 개 접속하는 것을 허용하는가? (예: Vishamos 2개)
    -> 여러개 허용한다. 메인쪽은 계속 켜두고, 개발하면서도 연결을 체크해야한다.
- `[확인 필요]` 텍스트(JSON) 메시지도 지원하는가? 현재는 바이너리 위주이고, 텍스트는 Echo만 한다.
    -> 초당 전송률을 위해 binary로 설정하였다.
- `[확인 필요]` 외부(다른 PC, 모바일)에서 접속하는가? 그렇다면 접속 인증이 필요하다. 현재는 누구나 접속해 등록할 수 있다.
  - -> 외부 접속은 어짜피 공유기 상으로 포트를 열어두지 않았다. 

### F-2. 치지직 채팅 연동
- F-2-1. 설정의 채널 ID로 채팅 채널 ID(`chatChannelId`)를 조회한다.
- F-2-2. 네이버 로그인 쿠키로 채팅 액세스 토큰을 발급받는다.
- F-2-3. 치지직 채팅 서버에 접속하고, 20초마다 하트비트를 보낸다.
- F-2-4. 채팅 메시지(93101)를 받는다.
- F-2-5. 후원 메시지(93102)를 받는다. (미구현)
- F-2-6. 연결이 끊기면 토큰을 다시 받아 재연결한다. (미구현)
- `[확인 필요]` 받은 채팅·후원을 어디로 보내는가? (Vishamos에 반응시키기? OBS 오버레이? DB 저장?) 현재 코드는 콘솔 출력만 한다.
- `[확인 필요]` 채팅 **송신**이 필요한가? 접속 권한은 `SEND`로 되어 있다.
    -> 송신은 일단은 염두해두고있지 않다.
- `[확인 필요]` 중계 서버 클라이언트가 목적지 `31`(치지직)로 보낸 메시지는 무엇을 의미하는가? (채팅 송신?)
    -> 치지직에 채팅이나 관리가 필요하다면 보낼 생각이다. (현재 게임 타입 변경 등등) 아직 고려하고 있지 않으니 기획에만 기억해둘 것.

### F-3. Discord 연동 `[확인 필요]`
- 목적지 식별값(`41`)만 있고 구현은 없다. 목적과 범위를 정해야 한다.

### F-4. OBS 연동 `[확인 필요]`
- 목적지 식별값(`51`)만 있고 구현은 없다.
- 방식 후보: (a) OBS 브라우저 소스가 중계 서버 클라이언트로 접속, (b) VishaSynapse가 obs-websocket에 접속해 장면·소스를 제어

### F-5. 데이터베이스 (MariaDB) `[확인 필요]`

- 후보: 채팅·후원 기록, 시청자 정보, 클라이언트 접속 기록, 설정

## 4. 비기능 요구사항
