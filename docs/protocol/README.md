# VishaSynapse 클라이언트 프로토콜

VishaSynapse(중계 서버)에 접속하는 클라이언트 앱(Vishamos, Face, Body 등)이 지킬 규칙이다.

- 기준: 기술 명세 [`docs/tech_spec/02_relay_server.md`](../tech_spec/02_relay_server.md). 이 문서는 그중 클라이언트가 지킬 부분만 옮긴 것이다. 둘이 다르면 명세가 맞고, 이 문서를 고친다.
- 갱신: 2026-11-18 (명세 02, Relay-1∼3 구현 기준)
- 공개 저장소이므로 서버 주소·내부 IP는 적지 않는다. 각 앱의 설정에 둔다.

---

## 1. 접속

| 항목 | 값 |
|---|---|
| 방식 | WebSocket (`ws://`) |
| 주소 | `ws://<서버 PC의 LAN IP>:<포트>`. 포트 기본값 4000 |
| 범위 | 같은 공유기 안(LAN)에서만 접속한다. 인터넷 쪽 접속은 없다 |
| 인증 | 없다 |

---

## 2. 시그니처 (기기 식별값)

메시지의 `to`(받는 쪽)와 `from`(보내는 쪽)에 쓰는 값이다. 1바이트(0∼255) 안에 들어간다.

| 값 | 대상 | 비고 |
|---|---|---|
| 0 | 서버 | 등록 등 서버에 보내는 명령의 `to` |
| 11 | Vishamos | 방송용·테스트용 클라이언트 모두 11로 등록한다(함께 받는다) |
| 21 | Face Android (Galaxy) | |
| 22 | Face iOS (iPhone) | |
| 31 | Body (웹캠 바디 트래커) | |
| 101 | 치지직 (서버가 처리) | 보류 중. 보내면 501 |
| 111 | Discord (서버가 처리) | 보류 중. 보내면 501 |
| 121 | OBS (서버가 처리) | 보류 중. 보내면 501 |

- 같은 시그니처로 여러 클라이언트가 동시에 접속할 수 있다. `to`가 X인 메시지는 X로 등록된 클라이언트 **모두**가 받는다.
- 여러 시그니처에 한 번에 보내는 묶음 값은 없다.

---

## 3. 등록

접속만으로는 메시지를 주고받을 수 없다. **접속 후 30초 안에** 등록해야 하며, 넘기면 서버가 연결을 끊는다(종료 코드 1008 `register_timeout`).

1. 접속하자마자 클라이언트가 **텍스트(JSON)** 로 등록을 보낸다. 서버가 먼저 보내는 메시지는 없으니 기다리지 않는다.
   ```json
   {"to":0,"from":22,"type":"client.register","data":""}
   ```
   `from`에는 자기 시그니처를 넣는다.
2. 서버가 등록 완료를 보낸다. `index`는 서버가 붙인 연결 번호다(서버를 다시 켜기 전까지 재사용하지 않음).
   ```json
   {"to":22,"from":0,"type":"client.registered","data":{"index":3}}
   ```
3. 이후 JSON·바이너리를 주고받는다.

등록 실패
- 표에 없는 시그니처로 등록하면 404 에러(§6)가 오고, 연결은 유지된다. 올바른 값으로 다시 등록하면 된다.
- 이미 등록한 연결이 다시 등록을 보내면 무시된다(현재 동작, 명세 보완 중: 이슈 #5).

---

## 4. 메시지 형식

간단한 명령은 JSON(텍스트), 실시간 갱신 데이터는 바이너리로 보낸다. 크기는 **64KB 이하**(넘으면 서버가 연결을 끊는다, 1009).

### 4.1 JSON (텍스트)
```json
{"to":11,"from":22,"type":"face.calibrate","data":{"...":"..."}}
```
| 키 | 내용 |
|---|---|
| `to` | 받는 쪽 시그니처 (정수) |
| `from` | 자기 시그니처 (정수). **등록한 시그니처와 다르면 전달되지 않고 400** |
| `type` | 메시지 종류 (문자열). 서버(`to`가 0·101·111·121)로 보낼 때는 필수 |
| `data` | 내용. 형식은 받는 쪽과 약속한다(서버는 보지 않는다) |

- 키는 소문자다(`To`처럼 대문자로 쓰면 없는 것으로 본다).

### 4.2 바이너리
```
[to (1바이트), from (1바이트), 데이터…]
예) Face iOS → Vishamos: [11, 22, 데이터…]
```
- `from`(두 번째 바이트)은 **반드시 등록한 시그니처**여야 한다. 다르면 서버가 그 클라이언트의 연결을 끊는다(종료 코드 1008 `from_mismatch`). 에러 메시지는 오지 않는다.
- 서버는 앞 2바이트만 읽고 **바이트를 바꾸지 않고** 그대로 전달한다.
- 데이터 안의 숫자는 **리틀 엔디언**으로 쓴다.
- 바이너리의 문제(대상 없음 등)에는 에러를 보내지 않는다. 초당 수십 번 오는 메시지라서다.

## 5. 서버가 보내는 메시지

| type | 언제 | 형식 |
|---|---|---|
| `client.registered` | 등록 성공 | `{"to":<내 시그니처>,"from":0,"type":"client.registered","data":{"index":<연결 번호>}}` |
| `error` | 아래 §6 에러 | `{"to":<내 시그니처>,"from":0,"type":"error","data":{"code":<코드>,"message":"<이름>"}}`. **등록 전에는 `to` 키가 없다** |

---

## 6. 에러와 연결 종료

### 6.1 에러 메시지 (JSON, 연결 유지)
| code | message | 언제 |
|---|---|---|
| 400 | `bad_request` | JSON 파싱 실패, `to`·`from`·`type` 누락·형식 오류, 중계하는 JSON의 `from`이 등록 시그니처와 다름 |
| 401 | `not_registered` | 등록 전에 등록 외의 메시지를 보냄 |
| 404 | `not_found` | 표에 없는 시그니처로 등록하거나 보냄, 받는 쪽에 연결된 클라이언트가 없음(JSON만) |
| 501 | `not_implemented` | 서버가 모르는 `type`, 보류 중인 요소(101·111·121)로 보냄 |
| 503 | `unavailable` | 기능은 있지만 지금 쓸 수 없음 (예: DB 연결이 끊긴 상태에서 DB 요청) |

### 6.2 연결 종료
| 종료 코드 | 이유 | 언제 |
|---|---|---|
| 1008 | `register_timeout` | 접속 후 30초 안에 등록하지 않음 |
| 1008 | `from_mismatch` | 바이너리의 `from`이 등록 시그니처와 다름 |
| 1009 | (라이브러리 기본) | 64KB를 넘는 메시지 |
| 1006 | (종료 신호 없음) | ping에 응답하지 않음 (§7) |

---

## 7. 연결 유지 (ping/pong)

- 서버가 30초마다 WebSocket ping을 보낸다. 클라이언트는 pong으로 답한다. 대부분의 WebSocket 라이브러리는 **자동으로** pong을 보낸다. 쓰는 라이브러리가 자동 응답하는지 확인한다.
- 다음 ping까지 pong이 없으면 서버는 그 연결을 "지연"으로 표시한다. pong 없이 5번 지나가면(마지막 pong 이후 약 2분 30초∼3분) 종료 신호 없이 끊는다.
- 끊기면 클라이언트가 다시 접속하고 다시 등록한다.

---

## 8. 메시지 크기

- 서버 한도: 메시지 하나에 **최대 64KB**(헤더 포함, JSON·바이너리 공통). 넘으면 연결을 끊는다(§6.2). 초당 횟수 제한은 없다.
- 메시지별 형식·크기·횟수는 서버 문서에 적지 않는다. **보내는 쪽**이 자기 사양에 형식과 최대 크기를 정한다.
- **받는 쪽**은 보내는 쪽 사양의 최대 크기 이상으로 수신 버퍼를 잡고, 받은 메시지의 길이를 확인해 맞지 않으면 버린다.

## 9. 옛 방식에서 바꿀 점 (기존 앱 수정용)

| 옛 방식 | 지금 |
|---|---|
| 접속 후 서버가 `[0, 0]`을 보냄 → 클라이언트가 `[0, 1, 식별값]`으로 등록 | 클라이언트가 바로 JSON `client.register`를 보냄 |
| 바이너리 첫 바이트만 목적지 (`[0a, 15, …]`) | 앞 2바이트가 `[to, from]` (`[11, 22, …]`) |
| Vishamos 10, Body 30 | Vishamos 11, Body 31 (10·30으로 등록하면 404) |
