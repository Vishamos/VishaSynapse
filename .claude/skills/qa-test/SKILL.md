# qa 테스트

## 1. 도구와 위치
| 항목 | 값 |
|---|---|
| 프레임워크 | `node:test` + `node:assert/strict` (새 의존성 없음) |
| 테스트 위치 | `test/<모듈명>.test.js` (커밋 대상) |
| 실행 | `node --test test/` |
| 시나리오 문서 | `docs/qa/<묶음 이름>.md` |
| 시나리오 로그 | `logs/qa-scenario.log` (git 제외됨) |

- `package.json`의 `test` 스크립트는 자리표시자라서 `npm test`를 쓰지 않는다.
- 문법 검사는 바뀐 파일마다 `node --check <파일>`.
- `.temp/`의 개발용 임시 스크립트는 참고하지 않는다.

## 2. 외부 통신 대체
- `https.get`·`fetch` → `mock.method(...)`로 가짜 응답
- ws → 테스트 안에서 `new WebSocket.Server({ port: 0 })`로 로컬 서버를 띄우고 끝나면 닫기
- mysql2 → `mock.method`로 대체
- 중계 서버는 `SocketServer(port)`로 기본이 아닌 포트(또는 `0`)에 띄운다.
- 환경 변수가 필요하면 테스트 안에서 더미 값(`'dummy'`)을 설정하고 `after`에서 원래대로 되돌린다.

## 3. 이 프로젝트의 제한
- 타이머(등록 30초, ping 30초×5회)를 줄이는 방법이 명세에 정해지기 전까지는 타이머 대기 테스트를 `test/`에 넣지 않는다("명세 보완 필요"로 보고).
- 바이너리 프로토콜 경계값: 빈 버퍼, 1바이트, 2바이트, 등록 전 클라이언트, 존재하지 않는 클라이언트 ID.
- 치지직 실연동, DB 실접속, 실기기(Vishamos·Face·Body)는 자동 테스트하지 않는다. 필요하면 사용자 시나리오나 "프로젝트 사이 확인 순서표"로 넘긴다.

## 4. 사용자 시나리오 로그
- 서버 콘솔 로그와 별개로, 시나리오용 이벤트는 `logs/qa-scenario.log`에 남긴다(형식은 qa 에이전트의 "로그 규칙"). **아직 이 파일에 쓰는 코드가 없다.** 시나리오가 필요하면 로그 지점 요청 이슈부터 올린다.
- 사용자는 실행 전에 이 파일을 지우거나 비운다(서버를 끈 상태에서 파일 삭제).
