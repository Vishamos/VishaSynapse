# 수정 절차

## 1. 분석
- `docs/work/worklist.md`에서 맡은 항목의 내용과 근거(기획 태그, 명세 절)를 확인한다.
- 항목에 적힌 **기술 명세(`docs/tech_spec/`) 절을 읽는다.** 구현 기준은 명세이며, 노션 기획서 원본은 참조하지 않는다.
  - 명세가 없거나, 명세에 없는 내용을 정해야 하거나, 명세와 코드가 충돌하면 **추측하지 말고 중단**하고 "명세 보완 필요"로 보고한다.
- 대상 파일을 처음부터 끝까지 읽는다.
- Grep으로 대상 함수·모듈의 사용처(`require`, 호출부)를 찾아 영향 범위를 확인한다.
- 승인된 수정 방향과 실제 코드가 맞지 않으면(이미 고쳐졌거나, 방향대로 하면 다른 곳이 깨지는 경우) 수정하지 말고 보고한다.

## 2. 수정
- 승인된 범위 안에서만 Edit로 수정한다.
- `node-coding-rule` 스킬의 표준을 따른다.
- 기존 파일을 삭제 후 재생성하지 않는다. 줄바꿈(CRLF)과 인코딩을 유지한다.

## 3. 자체 확인 (에러가 없는지만 본다)
1. **문법 검사** (프로젝트 전체):
   ```bash
   find . -name '*.js' -not -path './node_modules/*' -not -path './.claude/*' -print0 | xargs -0 -n1 node --check
   ```
2. **모듈 로드** (바뀐 모듈마다):
   ```bash
   node -e "require('./<파일>')"
   ```
   require하는 순간 외부 통신이 일어나는 모듈이면 실행하지 않고 보고에 적는다.
3. **로컬 실행** (중계 서버 관련 변경일 때). 사용자가 기본 포트로 서버를 띄워 둘 수 있으므로 기본 포트가 아닌 포트(예: 47125)를 쓴다:
   ```bash
   node -e "require('./VishaSynapse/VSServer').SocketServer(47125); setTimeout(() => process.exit(0), 1500)"
   ```
   - 에러 없이 기동 로그가 나오고 1.5초 뒤 종료되면 통과.
   - 포트가 이미 사용 중(`EADDRINUSE`)이면 실패로 보지 말고 그 사실만 보고한다.
4. **동작 테스트** (가짜 클라이언트로 메시지·타이머를 확인할 때):
   - 스크립트는 프로젝트의 `.temp/`(git 제외 폴더)에 **Write 도구로** 만든다. 셸 heredoc이나 Claude 임시 폴더(scratchpad)는 쓰지 않는다.
   - 실행은 `node .temp/<파일>.js` **한 줄로만** 한다. `cd` 등 다른 명령을 앞뒤로 붙이지 않는다(붙이면 허용 규칙에 맞지 않아 승인 요청이 뜬다).
   - `127.0.0.1`과 기본이 아닌 포트만 쓴다. DB, 치지직, `VishaCore.js`, `.env`는 다루지 않는다. `.temp/` 스크립트는 승인 없이 실행되므로 이 제한을 반드시 지킨다.
   - 대상: 실사용에서 일어나기 어려운 실패 경로(에러 코드, 시간 초과, 용량 초과)와 정상 연결 1개. 실제 기기 연동과 장시간 안정성은 사용자가 테스트한다.
   - 끝나면 스크립트를 지운다.
5. **실행하지 않는 것**: `VishaCore.js`, 치지직 API 호출, DB 접속. 필요하면 사용자 승인을 받는다.

## 4. 보고
- 처리 항목(기획 태그·명세 절 포함), 변경 파일(파일:줄), 자체 확인 결과, 범위 밖 발견 사항, 명세 보완 필요 사항.
- 동작 테스트를 했으면 "확인한 항목"과 "사용자가 확인할 항목"(실제 기기 연동 등)을 나눠 적는다.
- **흐름 대응표**: 바꾼 모듈·함수가 명세의 어느 절을 구현하는지 `함수 → 명세 §` 표로 적는다. 사용자는 JS보다 C#에 익숙하므로, 낯선 개념은 C# 대응을 짧게 붙인다(예: `Set` = `HashSet`, `async/await` = `Task`, `ws.on('close')` = event 핸들러).
- 범위 밖 발견(다른 영역의 문서·규칙 수정 필요, 명세 밖 버그)은 고치지 않고 보고서에만 적는다. 이슈는 만들지 않는다.
- 커밋은 메인 세션이 한다.
- 구현 기록(`docs/implementations/`)은 사용자가 요청한 경우에만 작성한다.
