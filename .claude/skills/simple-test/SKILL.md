# 최소 실행 테스트

에러 없이 돌아가는지만 본다. 명세 기준 단위 테스트(`test/`)는 qa가 쓴다(`qa-test`).

## 허용된 명령
아래 두 형태만 승인 없이 실행된다. 다른 명령을 `&&`·`;`로 붙이면 승인 요청이 뜨므로 **한 줄에 하나씩** 실행한다.
- `node --check <파일>`
- `node .temp/<파일>.js`

## 1. 문법 검사
바뀐 `.js` 파일마다 `node --check <파일>`.

## 2. 모듈 로드 (바뀐 모듈마다)
`.temp/load-check.js`를 **Write 도구로** 만들어 바뀐 모듈을 `require`만 하고 끝낸 뒤 `node .temp/load-check.js`로 실행한다.
- require하는 순간 외부 통신(DB, 치지직)이 일어나는 모듈이면 실행하지 않고 보고에 적는다.

## 3. 로컬 기동 (중계 서버 관련 변경일 때)
사용자가 기본 포트로 서버를 띄워 둘 수 있으므로 **기본이 아닌 포트 47125**를 쓴다. `.temp/boot-check.js`에 다음 내용을 쓰고 실행한다.
```js
require('../VishaSynapse/VSServer').SocketServer(47125);
setTimeout(() => process.exit(0), 1500);
```
- 에러 없이 기동 로그가 나오고 1.5초 뒤 종료되면 통과.
- 포트가 이미 사용 중(`EADDRINUSE`)이면 실패로 보지 말고 그 사실만 보고한다.

## 4. 동작 확인 (가짜 클라이언트로 메시지·타이머를 볼 때)
- 스크립트는 `.temp/`(git 제외)에 **Write 도구로** 만든다. 셸 heredoc이나 scratchpad는 쓰지 않는다.
- `127.0.0.1`과 기본이 아닌 포트만 쓴다. DB, 치지직, `VishaCore.js`, `.env`는 다루지 않는다. `.temp/` 스크립트는 승인 없이 실행되므로 이 제한을 반드시 지킨다.
- 대상: 고친 동작의 실패 경로(에러 코드, 시간 초과, 용량 초과)와 정상 연결 1개. 실제 기기 연동과 장시간 안정성은 사용자가 확인한다.

## 5. 정리와 보고
- 끝나면 `.temp/`에 만든 스크립트를 지운다.
- 보고: 1∼4 각각 통과/실패/생략과 이유. 동작 확인을 했으면 "확인한 것"과 "사용자가 확인할 것"을 나눈다.
